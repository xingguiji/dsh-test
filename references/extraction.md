# 取文与降级

摘要出错，十次有八次是正文没拿全就开始写。这一页只解决一件事：**在动笔之前确认自己拿到的是什么**。

## 一、完整性自检（必做，30 秒）

抓完先看四个地方：

1. **结尾**——是否停在句子中间？最后一段是不是"关注我们 / 版权声明 / 相关阅读"？
2. **省略标记**——`[+N chars]`、`[...]`、`[truncated]`、`（内容有删减）`。
3. **长度与声称**——标题像长文（"万字长文""年度报告"），正文却不足 800 字。
4. **开头**——是否从中间开始？第一句是不是半截话。

任一命中，就按下面的降级策略走，并在输出开头声明。

## 二、噪音清洗

正文之外的东西混进来，会让"骨架"这一节失真。删掉：

- 导航栏、面包屑、侧边栏、页脚、版权
- 评论区、作者简介、"相关推荐""热门文章"
- 订阅引导、打赏、二维码、"点击关注"
- 文末的推广段落（保留它的**存在**这个事实，写进"立场与前提"，但不当作论证）

判断技巧：真实正文的句子有主语和动词，且经常出现具体的名词（机构、产品、数字）。导航和推广大多是动词短语或无主句。

## 三、超长文（超过约 2 万字）

不要一遍硬读。分块：

1. 按小标题切成 N 块（每块 3000-6000 字）。
2. 每块只记三样：本块要解决的问题、给出的答案、用到的材料。
3. 合并时先看块与块之间有没有**互相矛盾**或**重复论证**——这是长文最容易出问题的地方。
4. 输出里写明："全文 2.4 万字，分 5 块读取"。

## 四、拿不到全文

| 情况 | 处理 |
| --- | --- |
| 付费墙 / 登录墙 | 声明"仅读到公开部分"，只用读到的写；不要用别人的二手转述补全，除非用户提供 |
| 抓取被压缩或省略 | 先找宿主提供的完整文本（DSH 会把完整抓取结果落盘，路径在结果里），读那个文件；没有就分段抓 |
| 只有标题和开头 | 只做 `one-line`，并说明"信息不足以判断结构" |
| 内容以图片/幻灯片为主 | 声明"只能做结构级总结，无法逐字核对"；若有图注，按图注推结构 |
| 视频 / 播客无字幕 | 要求用户提供转录稿，或说明只能基于简介 |

**绝不要**为了让摘要显得完整而编造后半部分的内容。半份简报 + 一句声明，比一份看起来完整实则虚构的简报有用得多。

## 五、非文本输入

| 格式 | 做法 |
| --- | --- |
| PDF | 先转文本再读；扫描件需要 OCR，读不出字就声明 |
| DOCX / PPTX | 用对应工具抽出正文；PPT 按页记结构，一页一句 |
| 网页存档（HTML） | 同上做噪音清洗 |
| 聊天记录 / 邮件线程 | 按时间排序，标出发言人，摘要时区分"谁主张" |

## 六、语言

- 原文是外语、用户用中文提问：输出中文，专有名词保留原文，关键判断句可在括号里附原文。
- 引文永远保留原文，不改写、不翻译；要翻译就放在括号里。
- 双语文章（中英混排）以正文主体语言为准。

## 七、读完之后记一笔

写简报前，先在心里填这张表——填不满就别写：

```
来源      ：<URL 或文件路径>
抓取方式  ：<工具 / 人工粘贴 / 转录>
读到范围  ：<全文 / 前 N 节 / 约 X 字>
缺失部分  ：<无 / 第 N 节之后 / 付费墙后>
原始长度  ：<字数，若有>
```

这份表里除"来源"外不必全部写进输出，但**"读到范围"和"缺失部分"必须在输出开头出现**（若无缺失可省略）。
