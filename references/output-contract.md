# 输出契约

三档模板。小节名固定，顺序固定——这样用户读第二篇时不用重新找位置。

## 锚点约定

| 写法 | 指向 |
| --- | --- |
| `[§3]` | 第 3 个小节（按原文小标题计数，从 1 起） |
| `[¶12]` | 第 12 段（无小标题的长文按自然段计） |
| `[L120-134]` | 行号（输入是本地文件或带行号的文本时） |
| `[表1]` `[图2]` | 原文的表格与插图 |

锚点服务于"用户能回原文核对"。宁可少写一条要点，也不要写一条无法定位的要点。

---

## 档位一：`one-line`

```
<一句话结论>。
可读性：<值得读 / 只读第 X 节 / 不必读>——<半句理由>。
```

约束：结论 ≤ 60 字，必须是**判断**而不是**描述**。

- ✅ "作者认为 Agent Skill 的竞争已从模型能力转向‘手艺’，但证据主要是星数增速，无法支撑这个结论。"
- ❌ "本文介绍了 GitHub 本周热榜的 16 个项目及其特点。"

---

## 档位二：`five-min`（默认）

```
## 结论
<1-2 句。作者到底想让读者相信什么。>

## 骨架
<章节树，3-7 行，用缩进表示层级。只写真实论证线，不抄目录。>

## 逐节要点
### §1 <小标题或"引子">
- <要点> [§1]
- <要点> [§1]

### §2 <小标题>
- ...

## 关键证据
| 主张 | 证据 | 类型 | 可核性 |
| --- | --- | --- | --- |
| C1 <一句话> | <数据/案例/引用> | 数据 / 案例 / 引用 / 类比 / 断言 | 可核 / 需一手来源 / 无法核实 |

## 立场与前提
- **作者位置**：<作者是谁、代表谁说话、有没有利益相关>
- **隐含前提**：<作者没说但必须先成立的那个假设>

## 存疑之处
- <最站不住的一条，说清为什么>
- <最值得追查的一条，说清去哪里查>
```

上限：中文 700 字，英文 450 词。`关键证据` 表最多 6 行——挑最承重的，不是最全的。

---

## 档位三：`outline`

在 `five-min` 的基础上：

1. `逐节要点` 升级为**逐节结构**，每节补三行：本节要解决的问题 / 给出的答案 / 用到的材料。
2. 增加 `## 论证链`：把 C1→C2→C3 的依赖关系画出来，标出哪一环断了论证就塌。
3. 增加 `## 可执行项`（仅当文章是 how-to 或报告）：能从文章直接照做的动作，逐条列，去掉套话。
4. 增加 `## 名词表`（可选）：原文自造词或行话，一句解释一个。

上限：中文 2000 字。

---

## 禁止句式

这些句子什么信息都不携带，出现即删：

- "本文探讨了……" / "文章主要介绍了……"
- "作者认为" 连着 "总之"（作者认为的是哪一句，直接写那句话）
- "随着……的发展" / "在当今……背景下"
- "值得一提的是" / "不难发现" / "由此可见"
- "结构清晰、论证严密" / "内容丰富、深入浅出"（这是评价，不是内容）
- "对……具有重要的参考价值"
- "综上所述，本文为我们提供了新的视角"

替换原则：**把评价换成事实，把概括换成原文里的那一句。**

---

## 三个容易犯的错

| 错法 | 后果 | 正确做法 |
| --- | --- | --- |
| 按小标题顺序复述 | 用户读完仍不知道作者在论证什么 | 先找论证线，再决定小节顺序 |
| 把作者的断言当结论复述 | 简报失去了"值不值得信"的判断 | 断言单独标注证据类型为"断言" |
| 把三档写成同一篇的截短版 | 短档失去信息密度，长档仍然空 | 短档只留结论 + 骨架；长档才展开证据 |
